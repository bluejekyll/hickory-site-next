0.25.0

v0.25.0 Mar 18 2025 at 21:01 UTC
<p>0.25.0 represents a large release for the Hickory DNS project. Over 14 months since 0.24.0, we've added two new maintainers, divergentdave and marcus0x62, and have addressed many limitations. A team from Ferrous Systems <a href="https://ferrous-systems.com/blog/hickory-dns-client/" rel="noopener noreferrer">shored up our support for DNSSEC</a>, and we addressed a number of findings from <a href="https://ostif.org/hickorydns-audit-complete/" rel="noopener noreferrer">our first security audit</a>.</p> <h2>Breaking changes</h2> <p>This is not an exhaustive list of changes, but here are some of the most impactful breaking changes in this release:</p> <ul> <li>Configuration for the Hickory DNS server crate has been reworked substantially to be more robust and secure. Most of the code related to the server binary has been moved out of the hickory-server library and into the hickory-dns binary crate.</li> <li>Support for TLS using native-tls or OpenSSL has been removed. We now only provide first-party support for rustls (0.23, for DNS over TLS, HTTP/2, QUIC and HTTP/3). We support <em>ring</em> or aws-lc-rs for cryptographic operations both for DNSSEC and TLS. The <code>dns-over-rustls</code>,<code>dns-over-native-tls</code>, <code>dns-over-openssl</code>, <code>dns-over-https-rustls</code>, <code>dns-over-https</code>, <code>dns-over-quic</code> and <code>dns-over-h3</code> features have been removed in favor of a set of <code>{tls,https,quic,h3}-{aws-lc-rs,ring}</code> features across our library crates.</li> <li>The synchronous API in the resolver and client crates, which previously provided a thin partial wrapper over the asynchronous API, has been removed. Downstream users will have to migrate to the asynchronous API.</li> <li>Support for the async-std runtime has been removed following the deprecation of the async-std crate by upstream (see their README). The async-std-resolver crate will no longer be updated.</li> <li>The DNSSEC API was reworked to extend coverage to the recursor, add support for NSEC3, and make the API more ergonomic and harder to misuse.</li> <li>Moved the <code>RuntimeProvider</code> API into the proto crate and use it consistently across the project.</li> <li><code>Name</code> values are now rooted by default in many places, and more consistently maintain their <code>fqdn</code> status.</li> <li>Error types are now exposed directly in the crate roots.</li> <li>Top-level TLS configuration in the resolver crate has moved to the <code>ResolverOpts</code> type. Specific <code>NameServerConfig</code>s should implicitly set up the ALPN protocol appropriate for the DNS protocol.</li> <li>The <code>ResolverOptions</code> fields <code>authentic_data</code> and <code>shuffle_dns_servers</code> were removed. The former field didn't do anything; and should be covered by new DNSSEC API. <code>shuffle_dns_servers</code> functionality has been subsumed into the <code>server_ordering_strategy</code> field.</li> <li>The use of rustls-native-certs via the <code>native-certs</code> feature was replaced with rustls-platform-verifier.</li> <li>The <code>tokio-runtime</code> feature was renamed to <code>tokio</code>.</li> <li>The <code>serde-config</code> feature was renamed to <code>serde</code>.</li> <li>Serializations (and what the new release can deserialize) has changed; data serialized by 0.24 may not deserialize correctly on 0.25, and vice versa.</li> </ul> <p>Please don't hesitate to file an <a href="https://github.com/hickory-dns/hickory-dns/issues" rel="noopener noreferrer">issue</a> or ask on our <a href="https://discord.gg/89nxE4n" rel="noopener noreferrer">Discord</a> server if you have issues upgrading.</p> <h2>Detailed changes since alpha.5</h2> <ul>
